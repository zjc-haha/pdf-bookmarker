# PDF 书签工具 {{VERSION}}（Windows 免安装版）

本版本仅用 DeepSeek 视觉模型识别 PDF 目录页。识别需要网络连接和 DeepSeek API Key。可处理单个 PDF，或递归处理整个文件夹。默认保留原 PDF，输出文件夹只保存生成的书签 PDF；勾选“直接覆盖原 PDF”后，成功处理的文件会在原位置替换，输出文件夹被忽略。报告与识别缓存在程序文件夹的 `data/jobs/` 中。

今后只提供免安装 ZIP，不再制作安装版。

## 启动与首次试跑

1. 将 ZIP **完整解压**。不要在压缩包内直接运行。
2. 打开解压后的 `PDF书签工具` 文件夹，双击 `PDF书签工具.exe`。
3. 选择单个 PDF 或文件夹后，左侧列出全部 PDF，包括预计跳过和无法读取的文件，并标出每本书的计划操作；筛选或选中一本书只改变清单和预览，运行整批时仍检查整个来源文件夹。中间可翻页、缩放或全屏预览；右侧可切换“现有书签”“识别结果”和“日志”，选中书签可跳到目标页。顶部显示预计识别、跳过和异常数量。
4. 选择输出文件夹，点击“处理设置”选择互斥的“核对并修正（推荐）”“只处理无书签”或“强制重建”。“仅分析”“续跑”和“直接覆盖原 PDF”是独立选项。选择直接覆盖时，输出文件夹会被忽略。识别需要网络连接和 [DeepSeek API Key](https://platform.deepseek.com/api_keys)；点击右上角“API Key”，在设置窗口的密码输入框填写密钥，也可预先设置 `DEEPSEEK_API_KEY` 环境变量。输入框失焦、开始处理或关闭窗口时，程序会把密钥用当前 Windows 用户的 DPAPI 加密，保存在 EXE 同级的 `data/deepseek-api-key.dpapi`；下次打开自动填入。旧版 `%LOCALAPPDATA%\PDFBookmarker\deepseek-api-key.dpapi` 会在首次读取时迁移，成功后删除旧文件。清空输入框不会删除已保存密钥；只有手动删除软件目录中的 `data/deepseek-api-key.dpapi` 才会清除它。
5. 首次使用先勾选“仅分析（仍调用 API）”，在界面中查看 `data/jobs/<任务编号>/` 下的报告；确认无误后再正式处理。需要改写原文件时再勾选“直接覆盖原 PDF（仅成功时替换）”，单本和整批均适用。运行完成后可在文件清单中筛选“失败”或“需复核”，右侧查看对应的识别书签和说明；需复核的书核对无误后，可点“确认并写入书签”。标题旁显示当前版本号，点右上角“帮助”或按 F1 可查看使用帮助。

请保留 `PDF书签工具.exe`、`PDF书签命令行.exe`、`_internal` 和运行后生成的 `data` 文件夹的相对位置；移动时一起移动整个 `PDF书签工具` 文件夹，才能保留密钥、报告和续跑数据。免安装版已包含 Python、PDF 处理库和 PDFium，适用于 64 位 Windows 10/11。当前构建未做代码签名，Windows 可能显示来源提示。

界面文字统一使用微软雅黑；日志把“第 1/20 本”等逐本进度单独加粗显示，文件名和处理结果另起一行。失败的文件行和失败日志以红色突出显示，便于在整批结果中定位。

## 命令行

在解压后的 `PDF书签工具` 文件夹打开 PowerShell。命令行从 `DEEPSEEK_API_KEY` 环境变量读取密钥；下面的设置只对当前 PowerShell 会话生效：

```powershell
$env:DEEPSEEK_API_KEY = Read-Host "DeepSeek API Key"

# 单本 PDF 先试跑，再正式处理
.\PDF书签命令行.exe single "D:\PDF书库\一本书.pdf" --output "D:\PDF书签结果" --dry-run
.\PDF书签命令行.exe single "D:\PDF书库\一本书.pdf" --output "D:\PDF书签结果"

# 文件夹批量处理；--limit 只取前 5 本
.\PDF书签命令行.exe batch "D:\PDF书库" --output "D:\PDF书签结果" --dry-run --limit 5
.\PDF书签命令行.exe batch "D:\PDF书库" --output "D:\PDF书签结果"

# 可选：成功时覆盖原 PDF，无需指定输出位置
.\PDF书签命令行.exe single "D:\PDF书库\一本书.pdf" --overwrite-original
.\PDF书签命令行.exe batch "D:\PDF书库" --overwrite-original

# 核对已有书签与印刷目录；只有不一致且识别可靠时才替换
.\PDF书签命令行.exe batch "D:\PDF书库" --output "D:\PDF书签结果" --verify-existing --dry-run
.\PDF书签命令行.exe batch "D:\PDF书库" --output "D:\PDF书签结果" --verify-existing

# 快速跳过任何已有书签的 PDF；单本和批量均适用
.\PDF书签命令行.exe single "D:\PDF书库\一本书.pdf" --output "D:\PDF书签结果" --skip-bookmarked
.\PDF书签命令行.exe batch "D:\PDF书库" --output "D:\PDF书签结果" --skip-bookmarked

# 核对需复核的结果后，按原任务的设置只重跑这一本并写入书签
.\PDF书签命令行.exe batch "D:\PDF书库" --output "D:\PDF书签结果" --verify-existing --accept-review "D:\PDF书库\一本书.pdf"
```

默认输出时，输出文件夹只保存生成的 PDF，文件名以 `_deepseek_bookmarked.pdf` 结尾；旧版留在该目录中的报告和缓存会迁到程序目录，供续跑继续使用。启用覆盖时，成功处理的 PDF 保留原路径和文件名，`--output` 路径被忽略。写入前的 PDF 临时文件和跨盘覆盖的原件备份都存放在程序目录 `data/temp/`；跨盘覆盖先备份、再写回并校验，失败时自动恢复。跨盘写回无法做到原子替换；若意外断电或强制终止，原文件可能暂时不可读，重新启动工具会检查恢复记录。`--dry-run` 不会替换文件，但报告仍写入 `data/jobs/<任务编号>/`。其中 `bookmarker-summary.csv` 和 `bookmarker-report.jsonl` 分别提供汇总与详细识别结果，识别缓存也在该任务目录中。

图形界面默认使用“核对并修正”；命令行可加 `--verify-existing` 启用。程序从印刷目录生成可信的章节标题、目标 PDF 页码及层级，与原书签比较：一致则跳过；缺失、多余、标题、目标页或层级不一致时，会在新输出 PDF 中替换旧书签。目录中成对括号包裹的阿拉伯数字页码（如 `(1)`、`（１）`）按数字页码解析；罗马数字 `i`、`ii`、`iii` 等非数字页码和无页码项目会被跳过且不生成书签。保留条目的页码映射不可靠时，报告标记 `needs_review`，不会写出可能错位的结果。若每个条目都已对应到可靠的 PDF 页、只是有警告（如目录页之间有一页没读出条目），可在界面“识别结果”中核对后点“确认并写入书签”，或在命令行加 `--accept-review <PDF>`；只重跑这一本，沿用识别缓存，不再调用 DeepSeek。目录页之间的插页若两次识别都判定不是目录页，且前后条目编号和页码首尾相接，不再标为需复核。默认保留原 PDF；启用覆盖时，失败或需人工复核的文件保持原样。扫描质量和目录结构不同，不能保证每本书都能成功识别。大量纯数字页码等低质量书签仍会触发重新识别；`--replace-existing` 或界面的“强制重建”用于直接重做已有合格书签。

书签层级优先按章节编号确定：“第 N 章”“Chapter N”为一级；书中有“第 N 章”时，“§1”“1.”等单个编号是章下的节；`1.1` 归在 `§1`、`1` 或第 1 章之下，`1.1.1` 再低一级，带星号的选学节同样识别；“第一章小结”这类与当前章同号的行是本章条目，不算新的一章。没有编号的条目按印刷目录的缩进放置，并参照同页有编号条目校准；例如 `Chapter 5` 下与 `5.1` 并列的 `Bibliography` 和 `Exercises` 都归在第 5 章下，书末独立的参考文献可保留为顶层条目。章内与小节同样缩进的“附录 1.1”等归在该章下，“绪论”等无章号标题下的小节归在该标题下；罗马数字编号的标题（如附录“I …”）之后的“1 …”“2 …”归在该标题下。生成的书签最前面有一条指向目录页的“目录”（英文书为“Contents”）书签。

若选择“只处理无书签”或加 `--skip-bookmarked`，只要文件有至少一条已有书签就记为 `skipped`，不调用 DeepSeek、不核对质量，也不修改原 PDF；没有书签的 PDF 仍正常处理。此模式默认关闭，单本和批量均适用。

## 图片上传与费用

工具会把需要识别的 PDF 页面渲染为图片发送到 DeepSeek API；PDF 原文件不会作为 PDF 上传。请只处理允许提交给该服务的文档。DeepSeek 按输入和输出 token 计费，图片也计入输入 token。图形界面默认核对现有书签，即使书签看起来完整也可能调用 API。`--dry-run` 只是不写入 PDF；首次识别仍会调用 API，可能产生费用。详见 DeepSeek 官方的[价格表](https://api-docs.deepseek.com/quick_start/pricing/)和[视觉输入说明](https://api-docs.deepseek.com/guides/vision/)。
